# 爆款工作台：可配置抓取 + 逐条 agent 分析

日期：2026-11-17
状态：已确认（方案 A：后端子进程直调 WorkBuddy CLI）

## 意图

把现有「热搜词 → MediaCrawler → 批量规则分析」升级成一个可操作的采集工作台：
用户自己选领域、自己定抓多少条，抓回来的内容带缩略图平铺展示，每条能跳原帖、
能单独丢给 WorkBuddy 做爆款拆解。

## 目标

- 抓取可配置：领域多选 + 自定义补充词 + 总条数上限 + 平台（小红书 / 抖音）
- 结果可浏览：封面缩略图、标题、作者、互动数据、平台标签
- 可跳转：点击直达原帖 / 原视频
- 可逐条分析：每条一个「分析」按钮，由 WorkBuddy agent 输出结构化拆解
- 与既有链路共存：原「热搜模式」和整批报告保留，不破坏已跑通的流程

## 非目标

- 不做视频本体下载（封面除外）
- 不做多账号池、不逆向签名、不绕风控
- 不在本步做视频生成（留给路线图第 3 步）

## 关键约束（实测得到）

1. **封面必须本地缓存**。小红书 `sns-webpic-qc.xhscdn.com` 的封面 URL 带签名时间戳，
   本次实测：01:37 抓到的链接在 09:55 返回 403（加 Referer、换 https 均无效）。
   前端直连必然裂图，只能抓取后立刻下载落盘，由后端代理读取。
2. **WorkBuddy CLI 当前无登录态**。本机 `codebuddy` CLI（v2.165.0）存在，
   `-p` 可非交互调用，但返回 `Authentication required`，且默认端口与桌面端冲突
   （`EADDRINUSE 127.0.0.1:58996`）。因此：每次调用指定随机空闲 `--port`；
   未登录时返回可读的引导文案，并降级为规则引擎，不让按钮变成死路。

## 方案取舍

### 领域 → 搜索词
- **选定**：内置领域表，每领域 6-10 个高命中词；前端多选 + 自定义补充框。
  稳定、零额外调用、命中率可预期（上一轮已实测短词命中真实高赞笔记）。
- 弃：agent 现场生成关键词（每次多 20-40 秒，命中率不可控）。
- 弃：领域只做热搜过滤（冷门领域热搜里常常一个词都没有）。

### 封面
- **选定**：抓取收尾批量下载到 `data/hot_capture/covers/`，前端走后端接口读。
  本地图还能直接喂给 agent 看图分析。
- 弃：前端热链（实测 403）。
- 弃：懒加载代理（首屏 60 次卡顿）。

### 单条分析结果
- **选定**：每条一个 JSON，落 `data/hot_capture/analysis/<platform>_<id>.json`。
  列表打「已分析」标记，重复点读缓存；后续生成视频可直接当输入。

### 调用 WorkBuddy
- **选定**：后端 `subprocess` 起 `codebuddy -p`，超时 180 秒，解析 JSON。
  同步返回，真 agent，能读本地封面图。
- 弃：任务队列 + 定时轮询（分钟级延迟，要求 WorkBuddy 常驻）。
- 弃：只用本地 vLLM（用户要的是 WorkBuddy 在做分析）。vLLM 仍保留为二级兜底。

## 实现结构

```
hot_capture/
  domains.py      领域表 + 关键词展开（含条数均分）
  cover_cache.py  封面下载 / 本地路径映射
  agent_cli.py    WorkBuddy CLI 定位、端口、调用、JSON 提取、错误分类
  pipeline.py     抓取任务编排（领域/热搜双模式）+ 任务状态机
  analyzer.py     + analyze_item()：单条 agent 分析（规则降级 + 结果缓存）
```

后端新路由（`sau_backend.py`）：

| 路由 | 方法 | 作用 |
|------|------|------|
| `/hotCapture/domains` | GET | 可选领域与词数 |
| `/hotCapture/capture` | POST | 建抓取任务，返回 task_id |
| `/hotCapture/task/<id>` | GET | 轮询任务状态与结果 |
| `/hotCapture/items` | GET | 列已抓条目（含本地封面地址） |
| `/hotCapture/cover/<file>` | GET | 读本地封面图 |
| `/hotCapture/analyzeItem` | POST | 单条分析（agent） |
| `/hotCapture/agentStatus` | GET | CLI 可用性 / 登录态探测 |

前端：`HotAnalysis.vue` 改造为工作台 —— 配置卡（模式/领域/条数/平台）、
卡片网格（封面 + 数据 + 看原帖 + 分析）、分析抽屉、Agent 配置卡保留。

## 留给实现者的部分

- 领域词表的具体词条可按实测命中率迭代
- 单条分析 prompt 的字段可小幅调整，只要保持 JSON 结构稳定
- 「多少条」按总上限算，内部按关键词均分，避免单词吃光额度
